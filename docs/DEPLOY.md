# Транслифт — установка и обслуживание сервера

Инструкция для администратора заказчика: установка, первый запуск, обновление, резервные копии, восстановление.

## Что понадобится

- **Сервер:** VPS с Linux (Ubuntu 22.04/24.04 или Debian 12), 2 vCPU, 4 ГБ RAM, диск от 40 ГБ. Фото — главный потребитель места, около 2–5 ГБ в год, см. экран «Хранилище» в приложении.
- **Домен:** например, `lift.example.ru`. DNS-запись типа A должна указывать на IP сервера.
- **Порты:** открыты 80 и 443. Остальные закрыты.
- **Docker** с плагином compose.

Сервер в РФ: персональные данные сотрудников хранятся на нём (152-ФЗ).

## Как это устроено

```
Браузер / телефон ──HTTPS──▶ Caddy (web) ──▶ backend (API) ──▶ PostgreSQL
                                │                   └────────▶ MinIO (фото и документы)
                                └─ отдаёт приложение (статика, PWA)
```

- Наружу открыт только Caddy. Он сам получает и продлевает сертификат HTTPS (Let's Encrypt).
- База (PostgreSQL) и хранилище файлов (MinIO) работают во внутренней сети Docker. Данные лежат в томах `translift-prod_pgdata` и `translift-prod_miniodata`.
- При каждом запуске backend сам применяет миграции базы данных.

## Установка

1. Установите Docker (официальный скрипт) и добавьте пользователя в группу `docker`:

```bash
curl -fsSL https://get.docker.com | sh
```

```bash
sudo usermod -aG docker $USER
```

После этого выйдите из сеанса и зайдите снова.

2. Скачайте код в `/opt/translift` (из архива, переданного при сдаче, или из репозитория):

```bash
sudo mkdir -p /opt/translift && sudo chown $USER /opt/translift
```

```bash
git clone <адрес репозитория> /opt/translift
```

3. Заполните настройки:

```bash
cd /opt/translift/deploy && cp .env.example .env && nano .env
```

- `DOMAIN` и `PUBLIC_URL` — ваш домен;
- `ACME_EMAIL` — почта для уведомлений о сертификате;
- `POSTGRES_PASSWORD`, `MINIO_PASSWORD` — длинные случайные строки, сгенерировать можно командой `openssl rand -base64 24`;
- `SEED_ADMIN_PASSWORD` — пароль первого администратора;
- `COMPANY_NAME` — подрядчик в шапке отчёта генподрядчику.

4. Соберите и запустите. Первая сборка занимает 3–5 минут:

```bash
docker compose --env-file .env up -d --build
```

5. Создайте шаблоны этапов и первого администратора. Повторный запуск безопасен:

```bash
docker compose --env-file .env exec backend npx prisma db seed
```

6. Откройте `https://ваш-домен` и войдите как `admin` с паролем из `SEED_ADMIN_PASSWORD`.
   - В **Профиле** смените пароль.
   - Удалите значение `SEED_ADMIN_PASSWORD` из `.env`.
   - В **Справочниках** заведите пользователей, бригады и договоры. Объекты можно загрузить из Excel на странице «Отчёты».

## Проверка

```bash
docker compose --env-file .env ps
```

```bash
curl -s https://ваш-домен/api/health
```

Все сервисы должны быть `Up (healthy)`, а `/api/health` — отвечать `{"status":"ok","db":true,"storage":true}`.

## Пользователи и пароли

Сотрудников заводит администратор в разделе **«Пользователи»**: ФИО, логин, роль. Пароль можно не вводить — система придумает временный и покажет один раз. Передайте его лично или по телефону; при первом входе сотрудник придумает свой.

- **Сотрудник забыл пароль.** Он нажимает «Забыли пароль?» на экране входа, администратору приходит уведомление. Администратор открывает «Пользователи» и нажимает «Выдать новый пароль». Перед этим стоит позвонить сотруднику и убедиться, что запрос от него.
- **Сотрудник уволился.** В его карточке снимите «Доступ разрешён». Он сразу выйдет из системы, его отметки и история останутся.
- **Пароль забыл единственный администратор:**

```bash
cd /opt/translift/deploy && docker compose --env-file .env exec -e SEED_ADMIN_RESET=true -e SEED_ADMIN_PASSWORD='временный-пароль' backend npx prisma db seed
```

Войдите как `admin` с этим паролем — система попросит придумать новый.

## Резервные копии

Скрипт `deploy/backup.sh` сохраняет базу (`pg_dump`) и все файлы (архив тома MinIO) в `deploy/backups`. Копии старше `BACKUP_KEEP_DAYS` дней (по умолчанию 14) удаляются.

Ежедневно в 3:30 — добавьте строку в `crontab -e`:

```
30 3 * * * cd /opt/translift/deploy && ./backup.sh >> backups/backup.log 2>&1
```

Вручную:

```bash
cd /opt/translift/deploy && ./backup.sh
```

> **Важно.** Копия на том же сервере не спасёт при потере сервера или диска. Настройте регулярный перенос папки `deploy/backups` в другое место: другой сервер (`rsync`), облачное хранилище (`rclone`) или хотя бы периодическое скачивание к себе. По договору резервное копирование после передачи выполняет заказчик.

## Восстановление из копии

```bash
cd /opt/translift/deploy && ./restore.sh
```

Без параметров скрипт покажет список копий. С меткой восстановит из неё, например `./restore.sh 2026-11-25_0330`. Скрипт спросит подтверждение. **Текущие данные заменятся данными из копии.** После восстановления всем пользователям нужно войти заново.

## Обновление до новой версии

```bash
cd /opt/translift && git pull
```

```bash
cd deploy && ./backup.sh && docker compose --env-file .env up -d --build
```

Миграции базы применятся при запуске. Пользователям с открытым приложением будет предложено «Обновить».

## Журналы и диагностика

```bash
docker compose --env-file .env logs -f --tail=100 backend
```

```bash
docker compose --env-file .env logs -f --tail=100 web
```

| Признак                                 | Что проверить                                                                |
| --------------------------------------- | ---------------------------------------------------------------------------- |
| Сайт не открывается, ошибка сертификата | DNS указывает на сервер, порты 80/443 открыты, логи `web`                    |
| «Сервер недоступен» в приложении        | `docker compose ps`, логи `backend`, `/api/health`                           |
| Не загружаются фото                     | Место на диске (экран «Хранилище»), логи `backend`                           |
| Заканчивается место                     | Экран «Хранилище» → «Очистка старых фото», перенос старых копий из `backups` |

## Перезапуск и остановка

```bash
docker compose --env-file .env restart
```

```bash
docker compose --env-file .env down
```

`down` останавливает контейнеры, данные в томах сохраняются. Тома удаляет только команда с ключом `-v`. **Не используйте её** без свежей резервной копии.

## Проверка без сервера

Рабочую сборку можно поднять на любом компьютере с Docker, без домена и HTTPS. Приложение откроется на http://localhost:8088. Создайте `deploy/.env.local` по образцу `.env.example` со строками `DOMAIN=:80`, `PUBLIC_URL=http://localhost:8088`, `COOKIE_SECURE=false`, `HTTP_PORT=8088`, `HTTPS_PORT=8443`. Затем:

```bash
COMPOSE_PROJECT_NAME=translift-local docker compose --env-file .env.local up -d --build
```

Скрипты копий работают так же: `ENV_FILE=.env.local COMPOSE_PROJECT_NAME=translift-local ./backup.sh`.
